# استخدام Study Tracker

قالب [`templates/study-tracker.md`](../templates/study-tracker.md) مصمم ليكون ملفاً شخصياً ينسخه كل متعلم إلى مجلده أو repository الخاص به. يفضل عدم وضع سجل شخصي مفصل داخل الريبو العام إذا كان يحتوي على معلومات خاصة؛ يمكن مشاركة نسخة منزوعة الخصوصية كدليل على الالتزام.

## دورة الاستخدام الأسبوعية

في بداية الأسبوع اختاري ثلاثة أهداف قابلة للتحقق من [`docs/study-plan.md`](study-plan.md). خلال الأسبوع سجلي جلساتك والمخرجات، ثم اربطي كل إنجاز بكود أو query أو ملاحظة. في نهاية الأسبوع قيّمي الثقة من 1 إلى 5، واكتبي failure واحداً وقراراً هندسياً واحداً تستطيعين شرحه.

| المرحلة | السؤال |
|---|---|
| Plan | ما الناتج المحدد الذي سأنتجه هذا الأسبوع؟ |
| Build | ما الكود أو التمرين الذي يثبت أنني نفذت؟ |
| Test | كيف اختبرت happy path وedge case وfailure؟ |
| Explain | هل أستطيع شرح القرار خلال خمس دقائق؟ |
| Review | ما الفجوة التالية ذات أعلى قيمة؟ |

## دلالات الحالة

استخدمي `Not started` عندما لا توجد محاولة، و`In progress` عندما توجد ممارسة غير مكتملة، و`Done` فقط عندما يوجد دليل قابل للمراجعة. مستوى الثقة ليس بديلاً عن الدليل؛ إذا كانت الثقة 5 ولا يوجد مشروع أو اختبار، فهذه إشارة لمهمة عملية جديدة.

## أفضل ممارسة للـ portfolio

لا ترفعي tracker شخصياً يحتوي على ساعات دقيقة أو معلومات مقابلات خاصة إلى repository عام. بدلاً من ذلك، ارفعي نسخة sanitized أو screenshot بسيطاً، واجعلي المشاريع والـ commits والـ README هي الدليل الأساسي على العمل.
